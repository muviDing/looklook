## 一、迁移功能问题分析与改造思路

### 1.1 问题①：复制-删除模式效率低下

#### 问题描述
- 当前采用`fs.promises.copyFile() + fs.promises.unlink()`的方式
- 大文件迁移速度慢，需要双倍磁盘空间
- 中途暂停可能导致文件冗余，无法正确清理

#### 根本原因分析
```javascript
// 当前实现方式
await fs.promises.copyFile(sourceFilePath, targetFilePath);  // 复制文件
await fs.promises.unlink(sourceFilePath);                   // 删除原文件
```
这种方式本质上是"复制+删除"，而不是真正的"移动"操作。

#### 改造思路
**方案A：使用Node.js原生移动API**
```javascript
// 推荐方案：使用fs.rename()
await fs.promises.rename(sourceFilePath, targetFilePath);
```
- 优点：原子操作，速度快，不占用额外空间
- 缺点：跨磁盘分区时会失败，需要降级到复制-删除模式

**方案B：调用Windows系统API**
```javascript
// 使用child_process调用系统命令
const { spawn } = require('child_process');
// 调用 move 命令或 robocopy 命令
```
- 优点：利用系统优化，支持系统进度显示
- 缺点：平台依赖性强，进度监控复杂

**方案C：混合策略（推荐）** //使用该方案
1. 首先尝试`fs.rename()`（同分区快速移动）
2. 失败时降级到`copyFile + unlink`（跨分区移动）
3. 添加中断恢复机制，记录已复制但未删除的文件

#### 实现要点
- 检测源文件和目标文件是否在同一分区
- 实现事务性操作，确保操作的原子性
- 添加中断恢复机制，应用启动时清理未完成的迁移

### 1.3 问题③：同名文件处理机制缺失

#### 问题描述
- 目标目录存在同名文件时直接失败
- 没有自动重命名机制
- 数据库记录无法正确更新

#### 改造思路
**文件名冲突解决策略**
```javascript
function generateUniqueFileName(targetDir, originalName) {
  const ext = path.extname(originalName);
  const baseName = path.basename(originalName, ext);
  let counter = 1;
  let newName = originalName;
  
  while (fs.existsSync(path.join(targetDir, newName))) {
    newName = `${baseName}(${counter})${ext}`;
    counter++;
  }
  
  return {
    fileName: newName,
    isRenamed: newName !== originalName,
    suffix: newName !== originalName ? `(${counter-1})` : null
  };
}
```

**数据库同步机制**
- 迁移成功后同时更新文件路径和文件名
- 在成功列表中标注重命名信息
- 提供批量重命名的撤销功能

**用户提示优化**

- 统计信息显示重命名文件数量

#### 2. GPU检测问题修复 - 影响核心功能

**A. 当前检测方法的局限性**

**存在的问题：**

**B. RTX 4070Ti无法使用GPU加速的可能原因**

**原因1：FFmpeg版本问题**
- 当前使用的FFmpeg可能是精简版，缺少NVENC支持
- RTX 40系列需要较新的FFmpeg版本（建议4.4+）
- 需要确保FFmpeg编译时包含`--enable-nvenc`选项

**原因2：驱动版本不匹配**
- RTX 40系列需要驱动版本≥522.25（Windows）
- NVENC API版本需要≥12.0
- CUDA版本需要≥11.8

**原因3：系统环境问题**
- Windows版本过低（建议Windows 10 1903+）
- 缺少Visual C++运行库
- NVIDIA控制面板中禁用了硬件加速

**改进的检测策略**

**A. 多层次检测机制**
```javascript
async function comprehensiveGpuCheck() {
  const results = {
    supported: false,
    details: {},
    recommendations: []
  };
  
  try {
    // 第1步：检测NVIDIA驱动和显卡信息
    const gpuInfo = await detectNvidiaGpu();
    results.details.gpu = gpuInfo;
    
    // 第2步：检测FFmpeg版本和编译选项
    const ffmpegInfo = await detectFfmpegCapabilities();
    results.details.ffmpeg = ffmpegInfo;
    
    // 第3步：检测CUDA和NVENC版本
    const cudaInfo = await detectCudaVersion();
    results.details.cuda = cudaInfo;
    
    // 第4步：实际编码测试
    const encodingTest = await performEncodingTest();
    results.details.encoding = encodingTest;
    
    // 第5步：综合评估
    results.supported = evaluateGpuSupport(results.details);
    results.recommendations = generateRecommendations(results.details);
    
  } catch (error) {
    results.error = error.message;
    results.recommendations.push('请检查NVIDIA驱动是否正确安装');
  }
  
  return results;
}

// 检测NVIDIA显卡信息
async function detectNvidiaGpu() {
  try {
    const { stdout } = await execFilePromise('nvidia-smi', [
      '--query-gpu=driver_version,name,memory.total,compute_cap',
      '--format=csv,noheader,nounits'
    ]);
    
    const [driverVersion, gpuName, memoryTotal, computeCap] = stdout.trim().split(', ');
    
    return {
      available: true,
      driverVersion,
      gpuName,
      memoryTotal: parseInt(memoryTotal),
      computeCapability: parseFloat(computeCap),
      isRtx40Series: gpuName.includes('RTX 40') || gpuName.includes('RTX 4'),
      minDriverRequired: gpuName.includes('RTX 40') ? '522.25' : '456.71'
    };

async function detectFfmpegCapabilities() {

    // 检测版本
    const { stdout: versionOutput } = await execFilePromise(ffmpegPath, ['-version']);
    const versionMatch = versionOutput.match(/ffmpeg version (\d+\.\d+)/);
    const version = versionMatch ? versionMatch[1] : 'unknown';
    
    // 检测编码器
    const { stdout: encodersOutput } = await execFilePromise(ffmpegPath, ['-encoders']);
    const hasH264Nvenc = encodersOutput.includes('h264_nvenc');
    const hasHevcNvenc = encodersOutput.includes('hevc_nvenc');
    
    // 检测编译配置
    const hasNvencSupport = versionOutput.includes('--enable-nvenc') || 
                           versionOutput.includes('--enable-cuda');
    
    return {
      version,
      hasH264Nvenc,
      hasHevcNvenc,
      hasNvencSupport,
      isVersionSufficient: parseFloat(version) >= 4.4
    };
  } catch (error) {
    return {
      available: false,
      error: 'FFmpeg不可用或版本检测失败'
    };
  }
}
```

```javascript
// 错误分类系统
const ErrorTypes = {
  RECOVERABLE: 'recoverable',     // 可恢复错误
  HARDWARE: 'hardware',           // 硬件相关错误
  PERMISSION: 'permission',       // 权限错误
  RESOURCE: 'resource',           // 资源不足错误
  CORRUPTION: 'corruption',       // 文件损坏错误
  NETWORK: 'network',             // 网络相关错误
  FATAL: 'fatal'                  // 致命错误
};

// 智能错误处理器
class SmartErrorHandler {
  static categorizeError(error) {
    const message = error.message.toLowerCase();
    
    if (message.includes('permission denied') || message.includes('access denied')) {
      return ErrorTypes.PERMISSION;
    } else if (message.includes('no space left') || message.includes('disk full')) {
      return ErrorTypes.RESOURCE;
    } else if (message.includes('no nvenc capable devices') || message.includes('gpu')) {
      return ErrorTypes.HARDWARE;
    } else if (message.includes('invalid data') || message.includes('corrupt')) {
      return ErrorTypes.CORRUPTION;
    } else if (message.includes('timeout') || message.includes('network')) {
      return ErrorTypes.NETWORK;
    } else if (message.includes('ffmpeg') && !message.includes('fatal')) {
      return ErrorTypes.RECOVERABLE;
    } else {
      return ErrorTypes.FATAL;
    }
  }
  
  static async handleError(error, context) {
    const errorType = this.categorizeError(error);
    const handler = this.getHandler(errorType);
    
    return await handler.handle(error, context);
  }
}
```
