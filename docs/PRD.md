# 早该看看了 - 本地视频管理工具 PRD 文档

## 1. 产品介绍

### 1.1 产品概述
"早该看看了"是一款基于Electron的本地视频管理桌面应用程序，为用户提供便捷的本地视频文件管理、组织和观看体验。本产品专注于解决用户在管理大量本地视频时面临的文件分散、信息混乱、查找困难等问题。

### 1.2 产品定位
本产品定位为个人视频库管理工具，适用于需要管理和整理大量本地视频文件的用户。它并非在线流媒体服务，而是专注于用户已下载或收藏的本地视频文件的管理。

### 1.3 用户画像
- **兴趣收藏者**：拥有大量视频收藏，需要归类整理的用户
- **学习者**：整理教学类视频，需要添加标签和分类的用户
- **内容创作者**：需要管理素材和作品的用户
- **影视爱好者**：需要整理电影、剧集和其他视频内容的用户
- **专业收藏者**：对视频资源有特定分类和标记需求的用户
- **本地资源管理者**：希望通过统一管理降低硬盘资源占用的用户

### 1.4 产品目标
- 提供简单易用的视频导入和管理功能
- 支持多种视图模式，满足不同用户的浏览习惯
- 提供完善的搜索和筛选功能，方便快速定位所需视频
- 记录观看历史和用户评分，帮助用户管理自己的观看体验
- 支持视频元数据的自定义和编辑，便于个性化分类管理
- 优化本地资源使用，提供重复视频的检测和清理功能
- 为专业收藏者提供完整的资源分类和整理工具

## 2. 功能需求

### 2.1 核心功能
- **视频导入**：支持导入本地视频文件，自动提取基本信息
- **视频管理**：支持对视频进行基本管理（添加、修改、删除、移动）
- **信息编辑**：支持编辑视频元数据（标题、分类、标签、演员、评分等）
- **视图切换**：支持表格视图和画廊视图的切换
- **搜索筛选**：支持基于多种条件的搜索和筛选功能
- **观看记录**：记录视频观看次数和最近观看时间
- **缩略图生成**：自动为视频生成缩略图预览，选取视频30%位置帧作为默认缩略图
- **重复检测**：自动识别和清理重复的视频条目
- **批量操作**：支持同时处理多个视频文件的批量功能
- **快速打开**：使用系统默认播放器快速打开视频
- **源文件夹访问**：快速访问视频所在的源文件夹
- **视频隐藏**：支持将不想展示但又不想删除的视频设为隐藏状态

### 2.2 扩展功能
- **数据备份**：支持数据导出和导入，便于迁移和备份
- **自动元数据获取**：基于文件名或特征自动获取视频元数据
- **视频预览**：支持在应用内直接预览视频片段
- **自定义分类**：支持用户自定义分类和标签系统
- **智能推荐**：基于观看历史和评分推荐类似内容
- **数据分析**：提供视频库的基本统计分析功能
- **多语言支持**：支持多种语言界面，包括中英文切换
- **自定义主题**：支持明暗主题切换或自定义颜色主题
- **缩略图更换**：支持用户手动更换视频的缩略图
- **网络元数据抓取**：从互联网获取视频相关信息
- **快捷操作**：支持键盘快捷键和右键菜单操作
- **视频转码**：提供基本的视频格式转换功能
- **视频质量分析**：自动检测视频分辨率和编码质量
- **文件夹监控**：自动监控指定文件夹，导入新增视频
- **批量重命名**：根据元数据规则批量重命名视频文件
- **自动清理**：根据用户设定的规则自动清理低质量或重复的视频

### 2.3 用户场景

#### 场景一：初次使用
1. 用户安装并首次启动应用
2. 应用引导用户导入视频文件
3. 系统自动分析视频文件并生成缩略图
4. 用户看到导入完成的视频库，可以开始管理和观看

#### 场景二：日常使用
1. 用户打开应用，可以看到已导入的所有视频
2. 用户可以根据需要切换表格视图或画廊视图
3. 用户使用搜索或筛选快速定位特定视频
4. 用户点击视频可以直接使用系统默认播放器观看
5. 系统自动记录观看次数和最后观看时间

#### 场景三：整理视频库
1. 用户选择多个视频进行批量操作
2. 用户对选中视频进行移动、标记或删除操作
3. 用户编辑视频的元数据信息，如添加标签、演员、评分等
4. 用户可以通过分类视图快速浏览不同类别的视频

#### 场景四：重复视频处理
1. 用户导入新视频后发现有重复
2. 用户点击"清理重复视频"按钮
3. 系统自动检测并显示重复的视频项
4. 用户审核并确认后，系统移除重复项但保留视频文件

#### 场景五：视频信息丰富化
1. 用户选择一个视频进入详情编辑模式
2. 用户填写视频相关信息（标题、演员、评分等）
3. 用户可以更换视频缩略图以获得更好的视觉识别效果
4. 系统保存更新的信息并在视图中反映这些变化

## 3. 界面设计

### 3.1 界面区域划分

应用界面从上到下分为以下六个主要区域：

#### A区域：标题栏和顶部按钮
- **功能**：显示应用标题，提供窗口控制按钮（最小化、最大化、关闭）和设置按钮
- **交互**：支持窗口拖动，按钮点击控制窗口状态
- **样式**：深色背景，白色文字，突出显示应用标题

#### B区域：搜索和筛选
- **功能**：提供搜索框和筛选按钮，用于快速查找和过滤视频
- **交互**：实时搜索，点击筛选按钮显示高级筛选选项
- **样式**：白色背景，搜索框带有搜索图标

#### C区域：操作按钮和视图控制
- **功能**：提供导入视频按钮，视图切换按钮（表格/画廊），表头设置按钮，排序按钮
- **交互**：点击按钮执行相应操作，视图切换按钮控制显示模式
- **样式**：浅灰色背景，突出显示主要操作按钮，次要按钮采用灰色调

#### D区域：视频列表
- **功能**：以两种视图模式显示视频内容
  - **表格视图**：以表格形式显示视频详细信息，包括文件名、标题、合集、演员等
  - **画廊视图**：以卡片形式显示视频缩略图和基本信息
- **交互**：支持选择、排序、点击操作。双击视频时直接使用系统默认播放器播放，右键点击可打开详情抽屉查看和编辑视频信息
- **样式**：白色背景，表格视图有固定表头，画廊视图采用网格布局

#### E区域：页脚
- **功能**：显示视频总数，提供分页控制，每页显示数量选择
- **交互**：点击页码切换页面，选择每页显示数量
- **样式**：浅灰色背景，清晰显示分页控件

#### F区域：详情抽屉
- **功能**：显示选中视频的详细信息，提供元数据编辑功能
- **交互**：点击视频时显示，可编辑各种元数据信息
- **样式**：侧边抽屉式设计，表单布局，编辑视频信息，响应式宽度调整

详情抽屉包含两种视图模式：

##### F-1：查看视图
- **功能**：以只读方式展示视频的完整元数据信息
- **内容**：包含缩略图预览、文件信息(文件名、路径、大小、创建时间等)和自定义元数据(标题、合集、演员、评分、备注等)
- **交互**：提供"编辑"按钮切换到编辑视图，"关闭"按钮隐藏抽屉
- **样式**：清晰的标签和数据展示，突出重要信息，提供分类展示

##### F-2：编辑视图
- **功能**：允许用户修改视频的元数据信息
- **内容**：包含表单控件(输入框、下拉菜单、评分控件等)，用于编辑视频的所有可编辑属性
- **交互**：提供"保存"按钮提交更改，"取消"按钮放弃更改并返回查看视图
- **样式**：友好的表单布局，提供输入验证和自动完成建议

#### G区域：导入进度弹窗
- **功能**：显示视频导入进度，提供取消导入选项
- **交互**：导入操作开始时自动显示，导入完成或取消时自动关闭
- **内容**：进度条、已处理/总数量统计、导入成功/失败数量、取消按钮
- **样式**：模态弹窗，突出显示进度信息，提供操作反馈

#### H区域：筛选浮窗
- **功能**：提供高级筛选选项，用于精确过滤视频列表
- **交互**：点击筛选按钮显示，点击应用按钮应用筛选并关闭，点击重置按钮清除筛选条件
- **内容**：包含多种筛选条件(合集、演员)
- **样式**：浮动面板，清晰的表单布局，条件选项分组展示

#### I区域：批量操作浮窗
- **功能**：提供批量操作功能，包括全选、反选、已选计数、移动到和移除按钮
- **交互**：当选中视频时自动显示在D区域底部，无选中时自动隐藏
- **样式**：浮动面板，固定在D区域底部中央，含阴影和半透明背景

#### J区域：表头设置浮窗
- **功能**：允许用户选择表格视图中显示的列
- **交互**：点击C区域表头设置按钮显示，点击浮窗外区域关闭
- **样式**：局部浮窗，靠近触发按钮定位，包含列选择复选框和操作按钮

#### K区域：排序设置浮窗
- **功能**：允许用户设置视频列表的排序规则
- **交互**：点击C区域排序按钮显示，点击浮窗外区域关闭
- **样式**：局部浮窗，靠近触发按钮定位，包含排序字段和方向选择

#### L区域：设置弹窗
- **功能**：显示设置信息
- **交互**：点击A区域设置按钮弹出，提供应用、重置、关闭
- **内容**：分类：①常规：启动时扫描文件夹（点击按钮添加文件夹路径到面板，允许添加多个，面板中换行显示）；②导入：标题正则解析式（单行文本，为空时提示词：为空时将不自动解析标题）；③关于：当前版本（V2.1.0）；意见反馈（联系方式：知乎-牧威，url：https://www.zhihu.com/people/mu-wei-33-5 ，可以做成卡片）
- **样式**：左右布局，左边按钮快速定位右侧内容分类，右边面板配置具体设置内容

### 3.2 视图模式

#### 表格视图
- 显示全面的视频信息，便于快速浏览和比较
- 支持列排序、多选和右键菜单操作
- 提供固定列功能，保证重要信息始终可见
- 列表包含：复选框、文件名、标题、合集、演员、分辨率、评分、观看次数、最后观看时间、备注、文件路径、文件大小、创建时间、上映时间等

#### 画廊视图
- 以网格形式展示视频缩略图，视觉效果更佳
- 显示关键信息，如文件名、评分、演员等
- 支持悬停显示更多信息，点击选中
- 卡片设计包含缩略图、文件名、主要标签和操作按钮

### 3.3 响应式设计
- 支持窗口大小调整，布局自适应
- 在小窗口模式下优化显示内容
- 视频卡片大小可调整，满足不同显示偏好
- 详情抽屉宽度可调整，提供更灵活的信息查看体验
- 表格视图支持列宽调整和列显示控制

## 4. 技术架构

### 4.1 技术栈
- **前端**：HTML/CSS/JavaScript, Tailwind CSS
- **框架**：Electron
- **数据库**：NeDB (嵌入式数据库)
- **视频处理**：FFmpeg (用于缩略图生成)

### 4.2 模块化代码结构

为了便于维护和快速定位问题，代码采用以下模块化结构：

#### CSS 模块化
- **layout.css**：主要布局样式，包含所有区域的基本样式定义
- 可考虑进一步拆分为区域特定样式文件

#### JavaScript 模块化
- **main.js**：应用入口，负责初始化和协调各模块
- **areaA.js**：标题栏功能实现
- **areaB.js**：搜索和筛选功能实现
- **areaC.js**：功能按钮和批量操作实现
- **areaD.js**：视频列表渲染和交互实现
- **areaE.js**：页脚和分页功能实现
- **areaF.js**：详情抽屉实现
- **videoData.js**：视频数据模型和数据处理函数
- **database.js**：数据库操作和持久化功能

### 4.3 数据流

1. **数据加载**：应用启动时，从NeDB数据库加载视频数据
2. **数据处理**：videoData.js 处理和管理视频数据
3. **视图渲染**：根据当前视图模式（表格/画廊）渲染视频列表
4. **用户交互**：用户操作触发相应模块的事件处理函数
5. **数据更新**：操作导致的数据变更通过统一接口处理并持久化到数据库
6. **视图更新**：数据变更后重新渲染相应视图

### 4.4 通信机制
- 使用Electron的IPC机制实现主进程和渲染进程间通信
- 使用JavaScript事件系统实现渲染进程内部模块间通信
- 使用统一的数据模型确保数据一致性
- 采用发布-订阅模式实现组件间的松耦合通信

## A. 需求分析与优先级

### A.1 核心需求来源分析
- **专业收藏者反馈**：通过对视频收藏爱好者的调研，发现对本地视频管理的强烈需求
- **现有工具缺陷**：市场上视频管理工具功能不完善、界面设计落后、安装包体积大
- **隐私保护需求**：用户希望在管理视频资源时保持隐私，不依赖云服务
- **组织效率提升**：帮助用户节省寻找特定视频的时间，提高内容获取效率

### A.2 功能优先级判断标准
功能优先级基于以下几个维度评估：
1. **用户价值**：该功能能为多少用户带来价值，价值程度如何
2. **开发成本**：实现该功能需要的时间和资源
3. **技术复杂度**：功能实现的技术挑战程度
4. **依赖关系**：功能之间的依赖和先后顺序
5. **差异化程度**：功能是否能形成与其他产品的差异化优势

### A.3 最小可行产品(MVP)定义
最小可行产品应包含以下功能，确保基本用户价值：
- 视频文件导入功能
- 基本元数据展示与编辑
- 表格视图展示视频列表
- 缩略图生成
- 视频基本搜索功能
- 使用系统默认播放器播放视频

## B. 用户体验优化建议

## 12. 技术架构详细说明

### 12.1 整体架构

#### 12.1.1 架构概览
"早该看看了"采用Electron框架构建，遵循主进程/渲染进程分离的架构模式。技术栈包括：
- **核心框架**: Electron
- **UI构建**: HTML/CSS/JavaScript + TailwindCSS
- **数据存储**: NeDB (嵌入式NoSQL数据库)
- **视频处理**: FFmpeg (缩略图生成和视频信息提取)
- **跨进程通信**: Electron IPC
- **文件系统交互**: Node.js fs模块

#### 12.1.2 模块组织
应用采用模块化设计，主要划分为以下几个核心模块：
- **UI层**: 负责界面渲染和用户交互
- **业务逻辑层**: 处理应用的核心业务逻辑
- **数据访问层**: 提供数据存取和持久化
- **系统交互层**: 负责与操作系统及外部程序的交互
- **核心服务层**: 提供通用功能服务(如配置、日志)

#### 12.1.3 技术选型考量
- **Electron**: 提供跨平台桌面应用开发能力，利用Web技术构建UI
- **NeDB**: 轻量级嵌入式数据库，无需额外安装数据库服务
- **TailwindCSS**: 提供高效的原子化CSS开发模式，加速UI开发
- **FFmpeg**: 强大的视频处理库，支持缩略图生成和元数据提取
- **原生JavaScript**: 避免引入过重的前端框架，保持应用轻量

### 12.3 数据模型

#### 12.3.1 核心数据实体
- **视频对象模型**
  ```javascript
  {
    id: "唯一标识符",
    filePath: "视频文件绝对路径",
    fileName: "文件名",
    fileSize: 1024000, // 文件大小(字节)
    thumbnailPath: "缩略图路径",
    
    // 元数据
    code: "视频标题/编号",
    collection: "所属合集",
    actors: ["演员1", "演员2"],
    releaseDate: "2023-01-01", // 上映日期
    rating: 4.5, // 用户评分(1-5)
    notes: "用户备注",
    resolution: "1920x1080",
    
    // 用户记录
    viewCount: 3, // 观看次数
    lastViewDate: "2023-05-20T14:30:00Z", // 最后观看时间
    
    // 系统记录
    createdAt: "2023-01-15T10:20:30Z", // 文件创建时间
    importDate: "2023-02-01T09:15:00Z", // 导入时间
    updatedAt: "2023-05-20T14:30:00Z" // 记录更新时间
  }
  ```

- **枚举值模型**
  ```javascript
  {
    type: "collection", // 枚举类型
    values: ["合集A", "合集B", "合集C"] // 枚举值数组
  }
  ```

#### 12.3.2 数据关系
- **一对多关系**: 一个合集包含多个视频
- **多对多关系**: 一个视频可以有多个演员，一个演员可以出现在多个视频中
- **动态枚举**: 所有分类值(如合集、演员)均为动态枚举，会随用户输入自动扩充

#### 12.3.3 数据存储
- **视频元数据**: 存储在NeDB数据库中
- **缩略图**: 存储在本地文件系统的专用目录
- **配置数据**: 存储在应用配置文件中
- **缓存数据**: 运行时保存在内存中，应用关闭前持久化

### 12.4 核心流程

#### 12.4.1 视频导入流程
1. 用户选择视频文件
2. 系统验证文件有效性
3. 提取基本文件信息(大小、创建时间等)
4. 使用FFmpeg提取视频元数据(分辨率等)
5. 生成视频缩略图
6. 创建视频数据记录并存入数据库
7. 将新导入的视频添加到UI显示

#### 12.4.2 数据更新流程
1. 用户编辑视频元数据
2. 前端验证数据有效性
3. 通过IPC发送更新请求到主进程
4. 主进程更新数据库记录
5. 发送更新成功通知给渲染进程
6. 渲染进程更新UI显示

#### 12.4.3 视频播放流程
1. 用户点击播放按钮
2. 系统调用默认视频播放器
3. 更新视频的观看次数和最后观看时间
4. 更新数据库记录
5. 更新UI中的相关信息

#### 12.4.4 搜索筛选流程
1. 用户输入搜索条件或设置筛选
2. 前端构建查询条件
3. 在缓存的视频数据中执行过滤
4. 根据结果更新视图
5. 对于复杂查询，通过IPC向主进程请求数据库查询

### 12.5 性能优化

#### 12.5.1 数据加载优化
- **增量加载**: 大量数据时分批加载
- **预加载策略**: 提前加载可能需要的数据
- **缓存机制**: 主要数据缓存在内存中，避免频繁数据库访问
- **索引优化**: 为常用查询字段建立索引

#### 12.5.2 UI渲染优化
- **虚拟列表**: 只渲染可视区域的元素
- **延迟加载**: 缩略图延迟加载
- **批量DOM更新**: 合并DOM操作，减少重绘
- **防抖与节流**: 对高频操作应用防抖和节流

#### 12.5.3 文件操作优化
- **异步操作**: 所有文件IO采用异步模式
- **操作队列**: 大量文件操作使用队列控制并发
- **缩略图缓存**: 优化缩略图存储和读取策略

#### 12.6.2 自定义配置
- **用户偏好设置**: 视图模式、排序方式、界面主题等
- **功能开关**: 可开启/关闭特定功能
- **性能调节**: 缓存大小、并发任务数量等
- **快捷键自定义**: 允许用户自定义快捷键

#### 12.6.3 数据导入导出
- **标准格式**: 定义标准的数据交换格式
- **批量导入**: 支持从其他应用批量导入数据

### 12.7 安全性考量

#### 12.7.1 本地安全
- **沙箱隔离**: 渲染进程在沙箱中运行
- **上下文隔离**: 启用Electron的上下文隔离
- **内容安全策略**: 实施严格的CSP
- **最小权限原则**: 仅请求必要的系统权限

#### 12.7.2 数据安全
- **数据验证**: 所有输入数据进行严格验证
- **路径规范化**: 防止路径遍历攻击
- **安全存储**: 敏感配置采用安全存储
- **异常处理**: 完善的错误处理和恢复机制

#### 12.7.3 应用完整性
- **代码签名**: 生产版本进行代码签名
- **更新验证**: 应用更新包进行完整性验证
- **依赖审查**: 定期审查依赖项的安全性
- **日志记录**: 关键操作进行日志记录，便于问题诊断
