# 早该看看了 - 本地视频管理工具 PRD 文档

## 1. 产品介绍

### 1.1 产品概述
"早该看看了"是一款基于Electron的本地视频管理桌面应用程序，为用户提供便捷的本地视频文件管理、组织和观看体验。本产品专注于解决用户在管理大量本地视频时面临的文件分散、信息混乱、查找困难等问题。

### 1.2 产品定位
本产品定位为个人视频库管理工具，适用于需要管理和整理大量本地视频文件的用户。它并非在线流媒体服务，而是专注于用户已下载或收藏的本地视频文件的管理。

### 1.3 用户画像
- **兴趣收藏者**：拥有大量视频收藏，需要归类整理的用户
- **学习者**：整理教学类视频，需要添加标签和分类的用户
- **内容创作者**：需要管理素材和作品的用户
- **影视爱好者**：需要整理电影、剧集和其他视频内容的用户
- **专业收藏者**：对视频资源有特定分类和标记需求的用户
- **本地资源管理者**：希望通过统一管理降低硬盘资源占用的用户

### 1.4 产品目标
- 提供简单易用的视频导入和管理功能
- 支持多种视图模式，满足不同用户的浏览习惯
- 提供完善的搜索和筛选功能，方便快速定位所需视频
- 记录观看历史和用户评分，帮助用户管理自己的观看体验
- 支持视频元数据的自定义和编辑，便于个性化分类管理
- 优化本地资源使用，提供重复视频的检测和清理功能
- 为专业收藏者提供完整的资源分类和整理工具

## 2. 功能需求

### 2.1 核心功能
- **视频导入**：支持导入本地视频文件，自动提取基本信息
- **视频管理**：支持对视频进行基本管理（添加、修改、删除、移动）
- **信息编辑**：支持编辑视频元数据（标题、分类、标签、评分等）
- **视图切换**：支持表格视图和画廊视图的切换
- **搜索筛选**：支持基于多种条件的搜索和筛选功能
- **观看记录**：记录视频观看次数和最近观看时间
- **缩略图生成**：自动为视频生成缩略图预览
- **重复检测**：自动识别和清理重复的视频条目
- **批量操作**：支持同时处理多个视频文件的批量功能
- **快速打开**：使用系统默认播放器快速打开视频
- **源文件夹访问**：快速访问视频所在的源文件夹

### 2.2 扩展功能
- **数据备份**：支持数据导出和导入，便于迁移和备份
- **自动元数据获取**：基于文件名或特征自动获取视频元数据
- **视频预览**：支持在应用内直接预览视频片段
- **自定义分类**：支持用户自定义分类和标签系统
- **智能推荐**：基于观看历史和评分推荐类似内容
- **数据分析**：提供视频库的基本统计分析功能
- **多语言支持**：支持多种语言界面
- **自定义主题**：支持明暗主题切换或自定义颜色主题
- **缩略图更换**：支持用户手动更换视频的缩略图
- **网络元数据抓取**：从互联网获取视频相关信息
- **快捷操作**：支持键盘快捷键和右键菜单操作
- **视频转码**：提供基本的视频格式转换功能
- **视频质量分析**：自动检测视频分辨率和编码质量

### 2.3 用户场景

#### 场景一：初次使用
1. 用户安装并首次启动应用
2. 应用引导用户导入视频文件
3. 系统自动分析视频文件并生成缩略图
4. 用户看到导入完成的视频库，可以开始管理和观看

#### 场景二：日常使用
1. 用户打开应用，可以看到已导入的所有视频
2. 用户可以根据需要切换表格视图或画廊视图
3. 用户使用搜索或筛选快速定位特定视频
4. 用户点击视频可以直接使用系统默认播放器观看
5. 系统自动记录观看次数和最后观看时间

#### 场景三：整理视频库
1. 用户选择多个视频进行批量操作
2. 用户对选中视频进行移动、标记或删除操作
3. 用户编辑视频的元数据信息，如添加标签、演员、评分等
4. 用户可以通过分类视图快速浏览不同类别的视频

#### 场景四：重复视频处理
1. 用户导入新视频后发现有重复
2. 用户点击"清理重复视频"按钮
3. 系统自动检测并显示重复的视频项
4. 用户审核并确认后，系统移除重复项但保留视频文件

#### 场景五：视频信息丰富化
1. 用户选择一个视频进入详情编辑模式
2. 用户填写视频相关信息（番号、演员、评分等）
3. 用户可以更换视频缩略图以获得更好的视觉识别效果
4. 系统保存更新的信息并在视图中反映这些变化

## 3. 界面设计

### 3.1 界面区域划分

应用界面从上到下分为以下六个主要区域：

#### A区域：标题栏和顶部按钮
- **功能**：显示应用标题，提供窗口控制按钮（最小化、最大化、关闭）和设置按钮
- **交互**：支持窗口拖动，按钮点击控制窗口状态
- **样式**：深色背景，白色文字，突出显示应用标题

#### B区域：搜索和筛选
- **功能**：提供搜索框和筛选按钮，用于快速查找和过滤视频
- **交互**：实时搜索，点击筛选按钮显示高级筛选选项
- **样式**：白色背景，搜索框带有搜索图标

#### C区域：操作按钮和视图控制
- **功能**：提供导入视频按钮，批量操作按钮（全选、反选、移动、移除），视图切换按钮（表格/画廊）
- **交互**：点击按钮执行相应操作，视图切换按钮控制显示模式
- **样式**：浅灰色背景，突出显示主要操作按钮

#### D区域：视频列表
- **功能**：以两种视图模式显示视频内容
  - **表格视图**：以表格形式显示视频详细信息，包括文件名、番号、合集、演员等
  - **画廊视图**：以卡片形式显示视频缩略图和基本信息
- **交互**：支持选择、排序、点击操作
- **样式**：白色背景，表格视图有固定表头，画廊视图采用网格布局

#### E区域：页脚
- **功能**：显示视频总数，提供分页控制，每页显示数量选择
- **交互**：点击页码切换页面，选择每页显示数量
- **样式**：浅灰色背景，清晰显示分页控件

#### F区域：详情抽屉
- **功能**：显示选中视频的详细信息，提供元数据编辑功能
- **交互**：点击视频时显示，可编辑各种元数据信息
- **样式**：侧边抽屉式设计，表单布局，编辑视频信息

详情抽屉包含两种视图模式：

##### F-1：查看视图
- **功能**：以只读方式展示视频的完整元数据信息
- **内容**：包含缩略图预览、文件信息(文件名、路径、大小、创建时间等)和自定义元数据(番号、合集、演员、评分、备注等)
- **交互**：提供"编辑"按钮切换到编辑视图，"关闭"按钮隐藏抽屉
- **样式**：清晰的标签和数据展示，突出重要信息，提供分类展示

##### F-2：编辑视图
- **功能**：允许用户修改视频的元数据信息
- **内容**：包含表单控件(输入框、下拉菜单、评分控件等)，用于编辑视频的所有可编辑属性
- **交互**：提供"保存"按钮提交更改，"取消"按钮放弃更改并返回查看视图
- **样式**：友好的表单布局，提供输入验证和自动完成建议

#### G区域：导入进度弹窗
- **功能**：显示视频导入进度，提供取消导入选项
- **交互**：导入操作开始时自动显示，导入完成或取消时自动关闭
- **内容**：进度条、已处理/总数量统计、导入成功/失败数量、取消按钮
- **样式**：模态弹窗，突出显示进度信息，提供操作反馈

#### H区域：筛选浮窗
- **功能**：提供高级筛选选项，用于精确过滤视频列表
- **交互**：点击筛选按钮显示，点击应用按钮应用筛选并关闭，点击重置按钮清除筛选条件
- **内容**：包含多种筛选条件(日期范围、文件大小、评分范围、标签选择等)
- **样式**：浮动面板，清晰的表单布局，条件选项分组展示

### 3.2 视图模式

#### 表格视图
- 显示全面的视频信息，便于快速浏览和比较
- 支持列排序、多选和右键菜单操作
- 提供固定列功能，保证重要信息始终可见
- 列表包含：复选框、文件名、番号、合集、演员、分辨率、评分、观看次数、最后观看时间、备注、文件路径、文件大小、创建时间、上映时间等

#### 画廊视图
- 以网格形式展示视频缩略图，视觉效果更佳
- 显示关键信息，如文件名、评分、演员等
- 支持悬停显示更多信息，点击选中
- 卡片设计包含缩略图、文件名、主要标签和操作按钮

### 3.3 响应式设计
- 支持窗口大小调整，布局自适应
- 在小窗口模式下优化显示内容
- 视频卡片大小可调整，满足不同显示偏好

## 4. 技术架构

### 4.1 技术栈
- **前端**：HTML/CSS/JavaScript, Tailwind CSS
- **框架**：Electron
- **数据库**：NeDB (嵌入式数据库)
- **视频处理**：FFmpeg (用于缩略图生成)

### 4.2 模块化代码结构

为了便于维护和快速定位问题，代码采用以下模块化结构：

#### CSS 模块化
- **layout.css**：主要布局样式，包含所有区域的基本样式定义
- 可考虑进一步拆分为区域特定样式文件

#### JavaScript 模块化
- **main.js**：应用入口，负责初始化和协调各模块
- **areaA.js**：标题栏功能实现
- **areaB.js**：搜索和筛选功能实现
- **areaC.js**：功能按钮和批量操作实现
- **areaD.js**：视频列表渲染和交互实现
- **areaE.js**：页脚和分页功能实现
- **areaF.js**：详情抽屉实现
- **videoData.js**：视频数据模型和数据处理函数
- **database.js**：数据库操作和持久化功能

### 4.3 数据流

1. **数据加载**：应用启动时，从NeDB数据库加载视频数据
2. **数据处理**：videoData.js 处理和管理视频数据
3. **视图渲染**：根据当前视图模式（表格/画廊）渲染视频列表
4. **用户交互**：用户操作触发相应模块的事件处理函数
5. **数据更新**：操作导致的数据变更通过统一接口处理并持久化到数据库
6. **视图更新**：数据变更后重新渲染相应视图

### 4.4 通信机制
- 使用Electron的IPC机制实现主进程和渲染进程间通信
- 使用JavaScript事件系统实现渲染进程内部模块间通信
- 使用统一的数据模型确保数据一致性

## 5. 开发规划

### 5.1 迭代计划
- **v1.0**：基础功能实现（导入、管理、观看视频）
- **v1.1**：UI优化，用户体验提升
- **v1.2**：高级筛选和搜索功能增强
- **v1.5**：元数据自动获取功能
- **v2.0**：数据分析和推荐系统
- **v2.5**：引入内置播放器功能
- **v3.0**：插件系统和扩展API支持

### 5.2 优先级划分
- **P0**：核心功能（视频导入、管理、查看）
- **P1**：用户体验优化（缩略图生成、视图切换）
- **P2**：高级功能（批量操作、元数据编辑）
- **P3**：扩展功能（数据备份、自动元数据获取）
- **P4**：增强功能（内置播放器、云同步）

### 5.3 风险评估
- **性能风险**：大量视频文件时的加载和管理性能
- **兼容性风险**：不同操作系统下的文件路径和播放器调用
- **用户体验风险**：界面复杂度与易用性平衡
- **资源占用**：缩略图存储和管理的磁盘占用
- **编码问题**：文件名和路径中的非ASCII字符处理
