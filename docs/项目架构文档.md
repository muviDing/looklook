# 早该看看了 - 项目架构文档

## 1. 项目概述

"早该看看了"是一款本地视频管理应用，基于Electron框架开发，旨在帮助用户方便地管理、组织和访问本地存储的视频文件。本文档详细描述项目的架构设计、技术实现和模块划分，为开发者提供全面的技术参考。

### 1.1 产品定位

本应用定位为轻量级本地视频管理工具，专注于：

- 本地视频文件的导入和管理
- 视频元数据的编辑和组织
- 视频缩略图的自动生成
- 视频浏览和快速访问
- 视频观看记录的跟踪

### 1.2 应用场景

- 个人视频收藏管理
- 影视资料分类整理
- 学习视频资源管理
- 多媒体素材库管理

## 2. 系统架构

### 2.1 总体架构

本项目采用Electron的主进程-渲染进程架构模式：

```
+---------------------------+
|      Electron 应用        |
+---------------------------+
|                           |
|  +-------------------+    |
|  |     主进程        |    |
|  | (Node.js 环境)    |    |
|  +-------------------+    |
|          |                |
|          | IPC通信        |
|          v                |
|  +-------------------+    |
|  |    渲染进程       |    |
|  | (Chromium 环境)   |    |
|  +-------------------+    |
|          |                |
+----------|----------------+
           v
+---------------------------+
|      外部资源/系统        |
|                           |
| - 本地文件系统            |
| - 默认视频播放器          |
| - NeDB数据库              |
+---------------------------+
```

### 2.2 核心模块划分

应用分为以下主要模块：

1. **主进程模块**：
   - 应用生命周期管理
   - 窗口管理
   - 文件系统操作
   - 数据库交互
   - 进程间通信
   - 视频处理（FFmpeg集成）

2. **渲染进程模块**：
   - 用户界面渲染
   - 用户交互处理
   - 视图管理
   - 数据展示和操作

3. **数据模块**：
   - 视频数据模型
   - 数据持久化
   - 数据缓存管理
   - 查询和筛选

4. **IPC通信模块**：
   - 安全API封装
   - 异步消息传递
   - 请求-响应模式实现

5. **UI功能区域模块**：
   - 标题栏区域(A)
   - 搜索筛选区域(B)
   - 功能按钮区域(C)
   - 视频列表区域(D)
   - 页脚和分页区域(E)
   - 详情抽屉区域(F)

## 3. 技术栈

### 3.1 核心技术

- **应用框架**: Electron v28.1.0
- **前端技术**: HTML5, CSS3, JavaScript (ES6+)
- **UI框架**: TailwindCSS v2.2.19

### 3.2 主要依赖库

- **fluent-ffmpeg**: FFmpeg JavaScript包装器

## 4. 模块详细设计

### 4.1 主进程模块 (main.js)

主进程是应用的核心，负责：

1. **应用生命周期管理**
   - 初始化应用环境
   - 创建主窗口
   - 处理应用关闭事件

2. **窗口管理**
   - 创建无边框窗口
   - 实现自定义标题栏
   - 处理窗口最小化、最大化、关闭等操作

3. **视频处理**
   - 使用FFmpeg生成视频缩略图
   - 提取视频元数据信息
   - 处理不同视频格式

4. **IPC事件处理**
   - 注册所有IPC事件处理程序
   - 处理渲染进程的请求

5. **文件系统操作**
   - 管理视频文件导入
   - 处理文件选择对话框
   - 维护缩略图目录

核心方法：
- `createWindow()`: 创建主应用窗口
- `registerIpcHandlers()`: 注册IPC事件处理程序
- `generateThumbnail()`: 生成视频缩略图
- `importVideos()`: 处理视频导入流程

### 4.2 预加载脚本 (preload.js)

预加载脚本实现了安全的IPC通信桥接：

1. **API暴露**
   - 使用contextBridge安全暴露API
   - 提供渲染进程与主进程通信的接口

2. **功能分类**
   - 窗口控制 API
   - 视频管理 API
   - 文件操作 API
   - 数据库操作 API

```javascript
// API示例
window.electronAPI = {
  // 窗口控制
  minimizeWindow: () => ipcRenderer.send('window-minimize'),
  maximizeWindow: () => ipcRenderer.send('window-maximize'),
  closeWindow: () => ipcRenderer.send('window-close'),
  
  // 视频管理
  importVideos: () => ipcRenderer.invoke('import-videos'),
  getVideos: () => ipcRenderer.invoke('get-videos'),
  // ...其他API
}
```

### 4.3 数据库模块 (database.js)

数据库模块封装了NeDB操作，提供：

1. **数据库初始化**
   - 创建并配置NeDB实例
   - 创建索引提高查询性能
   - 加载现有数据到内存缓存

2. **数据操作方法**
   - CRUD操作封装
   - 批量操作支持
   - 数据查询和筛选

3. **缓存管理**
   - 维护内存中的视频数据缓存
   - 同步缓存与数据库状态
   - 优化读取性能

4. **重复数据处理**
   - 检测重复视频记录
   - 清理冗余数据

核心方法：
- `initDatabase()`: 初始化数据库
- `saveVideo()`, `updateVideo()`, `deleteVideo()`: 基本CRUD操作
- `cleanupDuplicateVideos()`: 清理重复视频记录

## 5. 数据流

### 5.1 主要数据流程

1. **应用启动流程**

```
应用启动 → 初始化主进程 → 创建数据库连接 → 加载视频数据到缓存 
          → 创建主窗口 → 初始化渲染进程 → 渲染UI → 显示视频列表
```

2. **视频导入流程**

```
用户点击导入按钮 → 渲染进程发送IPC请求 → 主进程打开文件选择对话框 
                 → 用户选择文件 → 主进程处理文件 → 生成缩略图 
                 → 创建视频数据对象 → 保存到数据库 → 更新数据缓存 
                 → 返回结果给渲染进程 → 更新UI显示
```

3. **视频播放流程**

```
用户点击视频 → 渲染进程发送播放请求 → 主进程使用系统默认播放器打开视频 
            → 更新观看次数和时间 → 保存更新到数据库 → 更新UI显示
```

4. **视频编辑流程**

```
用户选择视频 → 打开详情抽屉 → 用户编辑信息 → 提交表单 
            → 渲染进程发送更新请求 → 主进程更新数据库 
            → 更新数据缓存 → 更新UI显示
```

```
+-------------------+       +-------------------+
```

## 6. 安全设计

### 6.1 上下文隔离

使用Electron的上下文隔离机制，防止渲染进程直接访问Node.js API:

```javascript
// main.js
mainWindow = new BrowserWindow({
  webPreferences: {
    preload: path.join(__dirname, 'preload.js'),
    contextIsolation: true,   // 启用上下文隔离
    nodeIntegration: false    // 禁用Node集成
  }
});
```

### 6.2 IPC通信安全

1. **最小权限原则**：仅暴露必要API给渲染进程
2. **输入验证**：主进程验证所有来自渲染进程的数据
3. **异步通信模式**：使用invoke/handle模式实现请求-响应

### 6.3 文件系统安全

1. **路径验证**：验证所有文件操作的路径
2. **文件类型限制**：限制可导入的视频文件类型
3. **异常处理**：文件操作异常的安全处理

## 7. 性能优化

### 7.1 数据缓存策略

1. **内存缓存**：使用videoCache缓存数据库中的视频数据
2. **增量更新**：仅更新变化的数据
3. **批量操作**：合并多个数据库操作

### 7.2 UI渲染优化

1. **延迟加载**：分页显示视频数据
2. **虚拟列表**：仅渲染可见区域的视频项
3. **节流和防抖**：优化搜索和筛选操作

### 7.3 资源利用优化

1. **缩略图优化**：
   - 合理的缩略图尺寸(320x180)
   - 优化的截取位置(视频时长的30%位置)
   - 可接受的图像质量

2. **FFmpeg优化**：
   - 仅在需要时生成缩略图
   - 非阻塞的处理方式

```javascript
// 动态API注册
function registerAPI(name, handler) {
  if (apiRegistry.has(name)) {
    throw new Error(`API ${name} already registered`);
  }
  apiRegistry.set(name, handler);
}

// 在预加载脚本中暴露API
const apis = {};
for (const [name, handler] of apiRegistry) {
  apis[name] = handler;
}
contextBridge.exposeInMainWorld('electronAPI', apis);
```

## 10. 总结

"早该看看了"项目采用现代化的技术栈和架构设计，通过模块化开发和关注点分离，实现了一个功能完备、性能优良、可扩展性强的本地视频管理应用。其核心特点包括:

1. **Electron主从进程架构**：充分利用Electron框架的特性，实现安全高效的桌面应用
2. **模块化UI设计**：按功能区域划分模块，提高代码可维护性
3. **高效数据管理**：结合NeDB和内存缓存，实现高效的数据访问
4. **FFmpeg集成**：利用FFmpeg实现视频缩略图生成和元数据提取
5. **安全通信机制**：使用上下文隔离和IPC机制确保应用安全

随着产品的迭代发展，架构设计将进一步优化，以支持更多高级功能和更好的用户体验。
