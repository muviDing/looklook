## 一、当前问题分析

### 1.1 主要问题
**问题描述**: 使用高效感知无损模式并启用GPU加速时，压缩出来的视频比原视频更大

**问题表现**:
- 原文件：1122MB
- 压缩后：2608MB
- 文件大小增加了132%

### 1.2 问题根因分析

#### A. GPU编码参数过于保守
```javascript
// 当前GPU参数配置
'-c:v', 'hevc_nvenc',
'-preset', 'p4',        // 中等预设，编码效率不够高
'-profile:v', 'main',
'-rc:v', 'vbr',
'-qmin', '0',           // 质量范围过大(0-28)
'-qmax', '28',
'-b:v', '0'             // 比特率控制不当
```

**问题分析**:
1. `preset p4` 是中等预设，在质量和速度之间平衡，但对于"感知无损"来说过于保守
2. `qmin=0, qmax=28` 质量范围过大，可能导致某些帧质量过高
3. 缺少高级编码优化参数，如自适应量化、前瞻等

#### B. 缺少原文件格式检测
- 没有检测原文件是否已经是高效编码格式
- 对已经优化的H.265文件进行重新编码会增大文件
- 缺少智能策略选择机制

#### C. 质量控制策略不当
- 使用VBR模式但参数配置不合理
- 没有针对不同分辨率调整参数
- 缺少基于内容的动态调整

## 二、优化策略

### 2.1 GPU编码参数优化

#### 优化方案A: 激进优化（推荐）
```javascript
// 高效感知无损 - GPU优化参数
// 目标：与CPU相当的压缩效果（1.1GB -> 300MB左右）
const gpuOptimizedParams = [
  '-c:v', 'hevc_nvenc',
  '-preset', 'p2',              // 更快预设，提高编码效率
  '-profile:v', 'main',
  '-rc:v', 'constqp',           // 改为恒定量化模式，与CPU的CRF类似
  '-qp', '28',                  // 直接使用28的量化参数，对应CPU的CRF 28
  
  // 高级优化参数
  '-spatial_aq', '1',           // 空间自适应量化
  '-temporal_aq', '1',          // 时间自适应量化
  '-rc-lookahead', '32',        // 增加前瞻帧数
  '-bf', '3',                   // B帧数量
  '-refs', '3'                  // 参考帧数量
];
```

#### 优化方案B: 保守优化
```javascript
// 保守优化 - 确保兼容性，但仍要达到相当压缩效果
const gpuConservativeParams = [
  '-c:v', 'hevc_nvenc',
  '-preset', 'p3',              // 稍慢但更稳定的预设
  '-rc:v', 'constqp',           // 恒定量化模式
  '-qp', '30',                  // 稍高的量化参数，确保兼容性
  '-spatial_aq', '1'
];
```

#### 关键问题分析
**当前问题根源**：
- CPU使用 `CRF 28`（恒定质量因子）
- GPU使用 `VBR模式 qmin=0 qmax=28`（可变比特率，质量范围过大）

**解决方案**：
- 将GPU改为 `constqp` 模式，使用 `qp=28` 直接对应CPU的CRF 28
- 这样可以确保GPU和CPU有相似的压缩效果

### 2.2 智能压缩策略

#### A. 原文件格式检测
```javascript
async function analyzeSourceVideo(videoPath) {
  const formatInfo = await detectVideoFormat(videoPath);
  
  return {
    container: formatInfo.container,
    videoCodec: formatInfo.videoCodec,
    audioCodec: formatInfo.audioCodec,
    bitrate: formatInfo.bitrate,
    isAlreadyOptimized: isHighlyCompressed(formatInfo)
  };
}

function isHighlyCompressed(formatInfo) {
  // 检测是否已经是高效编码
  const efficientCodecs = ['hevc', 'h265', 'av1'];
  const isEfficientCodec = efficientCodecs.includes(formatInfo.videoCodec?.toLowerCase());
  
  // 检测比特率是否已经很低
  const isLowBitrate = formatInfo.bitrate && formatInfo.bitrate < 2000; // 2Mbps
  
  return isEfficientCodec || isLowBitrate;
}
```

#### B. 动态参数调整
```javascript
function getDynamicCompressionParams(videoInfo, options) {
  const { resolution, duration, bitrate, isAlreadyOptimized } = videoInfo;
  
  // 如果已经高度优化，建议跳过或使用更保守参数
  if (isAlreadyOptimized) {
    console.warn('检测到文件已经高度优化，可能无法进一步压缩');
    return null; // 或返回保守参数
  }
  
  // 基于分辨率调整参数
  let cqValue = 24;
  if (resolution.includes('4K') || resolution.includes('2160')) {
    cqValue = 26; // 4K适当降低质量要求
  } else if (resolution.includes('1080')) {
    cqValue = 24; // 1080p保持高质量
  } else {
    cqValue = 22; // 720p及以下可以更高质量
  }
  
  return {
    cq: cqValue,
    preset: resolution.includes('4K') ? 'p3' : 'p2'
  };
}
```

### 2.3 压缩前预检查机制

```javascript
async function preCompressionCheck(videoPath, options) {
  const checks = {
    fileExists: fs.existsSync(videoPath),
    isReadable: false,
    diskSpace: 0,
    estimatedOutputSize: 0,
    shouldSkip: false,
    skipReason: ''
  };
  
  try {
    // 检查文件可读性
    await fs.promises.access(videoPath, fs.constants.R_OK);
    checks.isReadable = true;
    
    // 检查磁盘空间
    const fileSize = fs.statSync(videoPath).size;
    checks.diskSpace = await checkDiskSpace(path.dirname(videoPath));
    
    // 分析文件格式
    const videoInfo = await analyzeSourceVideo(videoPath);
    
    // 如果已经高度优化，建议跳过
    if (videoInfo.isAlreadyOptimized) {
      checks.shouldSkip = true;
      checks.skipReason = '文件已经高度优化，可能无法进一步压缩';
    }
    
    // 估算输出文件大小（基于经验值）
    if (options.mode === 'perceptual') {
      checks.estimatedOutputSize = fileSize * 0.6; // 预期减少40%
    }
    
  } catch (error) {
    console.error('压缩前检查失败:', error);
  }
  
  return checks;
}
```

## 四、故障排除

### 4.1 常见问题

**问题**: GPU压缩仍然比原文件大
**解决方案**: 
1. 检查显卡驱动是否最新
2. 尝试降低qp值到30或32
3. 检查原文件是否已经高度压缩

**问题**: GPU压缩速度没有提升
**解决方案**:
1. 确认GPU支持硬件编码
2. 检查系统资源占用
3. 尝试调整preset到p1（更快）

**问题**: 压缩质量下降明显
**解决方案**:
1. 降低qp值到26
2. 增加rc-lookahead到64
3. 启用更多高级参数

### 4.2 参数调优指南

**保守调优**（稳定性优先）:
```javascript
'-qp', '26',              // 更高质量
'-preset', 'p3',          // 更稳定的预设
'-rc-lookahead', '16'     // 较少的前瞻帧
```

**激进调优**（压缩率优先）:
```javascript
'-qp', '32',              // 更高压缩
'-preset', 'p1',          // 最快预设
'-rc-lookahead', '64'     // 更多前瞻帧
```
